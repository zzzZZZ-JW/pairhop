# 实测报告与发布验证

测试日期：2026-09-05。所有耗时都来自实际测量。此报告区分配对引擎基线与后续 CLI 发布变化，不将已实现、单元测试通过和完整设备验收混为一谈。

> 稳定性复核：下述 30 次测试使用了界面自动化工具读取 Chrome。后续用户正常重启复现了漏触发，发现工具的辅助功能访问会影响 Chrome 接口初始化。因此，这 30 次仍是有工具参与时的性能样本，**不能作为无人干预的重复触发成功率**。关闭所有窗口但保留 Chrome 进程也是独立路径，不能由完全退出测试替代。修复与新的验证口径见 [稳定性排查](stability-fix.md)。

## 30 次真实配对

每次实际退出并重新启动 Chrome，打开一个本地登录页，再点击官方启用密码填充入口。只测试扩展配对，没有提交网站登录。助手记录正向连接证据，界面工具另外读取到已连接文案、确认六位界面消失。

**30/30 确认连接，每次输入六位，未记录重复提交。** 单台设备的 30 次样本不代表所有环境的成功率。

| 区间 | 中位数 | P95 | 最大值 |
|---|---:|---:|---:|
| 来源、六格、焦点已就绪 → 确认六位输入完成 | 129.9 ms | 155.9 ms | 158.1 ms |
| 助手发现请求 → 输入完成 | 237.8 ms | 272.8 ms | 273.6 ms |
| 助手发现请求 → 确认连接 | 593.9 ms | 646.1 ms | 654.9 ms |
| 输入完成 → 观察到确认连接 | 350.1 ms | 373.4 ms | 413.0 ms |
| 界面工具发起点击调用 → 工具读取到连接结果 | 1150.5 ms | 1415 ms | 1425 ms |

P95 为 nearest-rank，即排序后的第 29 个样本。[逐次数据](evidence/pairing-baseline.csv) · [统计 JSON](evidence/pairing-summary.json)。公开数据移除了请求 UUID 和逐次时间戳，不包含验证码或页面信息。

最后一行含界面工具的通信、等待和状态读取开销，不能视为精确硬件点击计时。输入阶段包含 AX IPC 和逐位等待，不是纯 Swift CPU 时间。输入后的连接等待还包含最多 15 ms 重读间隔及 AX 调用，不能称为纯 Apple/Chrome 内部耗时；两个进程的内部耗时尚未分别归因。

## 15 分钟空闲

Chrome 关闭，交流电普通模式，原屏幕闲置设置已恢复。没有 Instruments 录制，也不查询助手状态。独立外部测量器每 60 秒读取一次 `proc_pid_rusage`，不会向助手发送信号。

| 指标 | 结果 |
|---|---:|
| 墙钟时长 | 900.087 s |
| CPU 时间增量 | 1.633 ms |
| 平均 CPU（一个逻辑 CPU 的 100% 为基准） | 0.00018145% |
| 平台空闲唤醒 | 0 |
| 中断唤醒增量 | 6 |
| 初始物理 footprint | 6,226,496 B |
| 最终 / 最大物理 footprint | 6,292,032 B |
| 磁盘 / 逻辑写入增量 | 0 B / 0 B |

[采样汇总](evidence/idle-summary.json)。CPU 用户态与内核态计数通过 `mach_timebase_info` 的 125/3 比率换算为纳秒。初版外部采集器曾误将 Mach ticks 标为纳秒；独立 100 ms 进程 CPU 时钟校准发现并修正了单位问题，最终换算与校准时钟比为 1.00035。本报告只使用修正值。

零平台空闲唤醒不等于所有唤醒为零。约 64 KiB 内存变化及 15 分钟样本不能证明数天无泄漏。该 CPU 结果也不能换算为整机瓦数或电池续航。

## Instruments

- **System Trace**：目标助手的 15.65 秒待命录制中，主线程持续 Blocked；线程 Running 总计约 0.182 ms、Runnable 约 1.697 ms，包含分析器开销。
- **Time Profiler**：15 秒录制仅一个 1 ms 权重样本，无可归因的有效调用栈；只说明采样活动稀疏。
- **停止对照**：另录制助手停止后的 System Trace，确认目标进程不存在。其他进程负载未受控，不推导整机功耗差。
- **Power Profiler**：实际录制失败，工具报告该仪器不支持 macOS、应在 iOS/iPadOS 录制。模板出现在列表不等于本机可用。

原始全系统 trace 可能包含其他应用信息，不进入公开仓库。

## 已执行的功能验证

v0.1.0：签名原生程序经 LaunchAgent 获得辅助功能及输入权限、30 次 Chrome 重启、停止并停用自动启动、恢复自动启动、异常退出约 9 秒后恢复、卸载、重装保留权限。接管前已有一位手动输入时保持一位，未追加数字。规则测试覆盖前导零、非 ASCII、伪装 URL 和错误输入进度。

v0.1.1 的发布检查另见 [release-validation.md](release-validation.md)，覆盖构建、签名、命令链接归属、安装器拒绝失败下载/校验错误和管理命令。CI 不进行真实 iCloud 配对。

## 未完成的验收

- 真正注销登录、真实睡眠唤醒、运行中撤销并重新授权。
- 中文等其他输入法；非简体中文/英语系统文案。
- 逐位输入期间切换应用、手动按键、关闭窗口的毫秒级竞争。
- 多个独立配对请求同时出现、真实伪装页面的界面测试。
- Chrome 普通浏览的停止/运行对照、配对阶段专项 Instruments 归因。
- 电池供电、低电量模式、绝对瓦数、数小时至数天稳定性。
- Intel 和其他系统版本兼容性、另一台 Mac 的 Gatekeeper / 首次授权流程。

这些项目不能用构建成功或现有单机数据替代。当前发布为预览版。
